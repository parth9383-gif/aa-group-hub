01

First impression — upar ka 381px

Visitor site kholte hi sabse pehle header aur hero dekhta hai. Yahin purani site sabse zyada haar rahi thi.

Kaise kiya

  • Nav = tumhari list ke hisab se (turn 38): logo/crest = Group, 5 tabs wahi jo tumne bole. Purana 7-tab layout hata kar clean 5-tab banaya.
  • Hero = Opus ka "Gold Thread" concept + Fable ka design (turn 37): headline sirf numbers se story kehti hai — 1 restaurant → 5 businesses → 100% giving.
  • Asli photo: company archive ki 2560px original (DSC02445) → 2400×1423 premium jpeg banayi (turn 38) → hero background.
  • Hover polish (turn 39): buttons mouse ke saath hilte the (magnetic/tilt effects) — hata diye, ab steady hain.

Proof

  • Purana header 381px tall — Chrome se live site pe measure kiya (viewport 1425px, 7 Nov 2026) — `_oldsite/measure-old.json`.
  • Purani nav mein sirf 2 links the — screenshot mein saaf dikhta hai.
  • "4 key divisions" claim + 5 divisions dono purani site pe the — khud se contradict karti thi (chapter 02 ka proof).
  • Nayi site: 5 tabs Chrome-test (click → sahi panel khulta hai), 0 JS errors.
02

Division clarity — 4 vs 5 ka jhagda

Group ki pehchaan hi divisions hain — purani site unhe theek se dikha hi nahi rahi thi.

Kaise kiya

  • Uniform CSS grid: har division ko same-size card — koi bada, koi chhota nahi.
  • Asli logos purani site se le kar local save kiye (`media/site/`) — koi dummy logo nahi.
  • Popeyes ko pehla rakha (turn 38 — tumhara instruction: Popeyes add karo, prominence ke saath): 60+ locations + Director of Ops ka naam.
  • Web Portal card: purana portal-link hata kar "Request access" mailto banaya (turn 38 — koi purane domain ka link nahi).

Proof

  • Purani grid ki rows measure ki gayin: 3 top pe (y≈1244), 2 neeche (y≈1644) — uneven layout ka pukhta saboot.
  • Purane page pe Cardio ka logo maujood tha (y≈1394) — isliye "4 key divisions" galat tha.
  • Nayi site: divisions tab ke 6 cards Chrome-verified; Popeyes card + asli logo render hota hai.
03

Numbers & claims — bina source ke daava

Purani site ne bade daave kiye bina kisi source, date ya footnote ke. Nayi site har number ka hisaab deti hai.

Kaise kiya

  • Numbers ek jagah lock (turn 37-38): 60+/1,200+/120/5/$75M+ — purane 42/$50M wale stale numbers hata diye (Fact Sheet confirm hone tak footnote rakha).
  • Footnote = "ye numbers kis point ke hain" wali line — trust isi se banta hai.
  • Recognition strip = sirf wahi cheezein jo public source se verify ho sakti hain: TRIEC page, urdupoint article, book ke khareedne ke stores — har link curl se check kiya (200 OK).

Proof

  • Purana "1,200 employees" daava bina kisi footnote ke tha — page ke poori DOM mein koi source text nahi (measure check).
  • Naye strip ke source links live hain: triec.ca 200 · urdupoint 200 · amazon 200 · gulfnews store 200 (curl, 8 Nov 2026).
  • Footnoted honesty: 60+/$75M figures pe Fact Sheet [CONFIRM] pending — jhooth nahi bola, pending dikhaya (QUESTIONS-LOG §C).
04

Footer & credibility — do copyright years

Sabse neeche wali line sabse zyada trust banati ya todti hai. Purani site ka footer khud ko galat bata raha tha.

Kaise kiya

  • Footer dobara banaya (turn 38): quick-links ab #anchors hain jo seedha tabs kholte hain (data-open-tab).
  • 15 purane links badle: Popeyes button → Contact, portal → mailto "Request access", contact-row → hub URL, JSON-LD/OG URLs → hub URL. Purane website ka link = 0.
  • Social icons ka centring bug fix + pixel-check (20px icons flex-centred).

Proof

  • © 2018 aur © 2025 dono purani site ke code mein mile (DOM scan) — © 2025 visible, © 2018 hidden line.
  • Nayi site: 0 old-domain links — grep (local) + curl (LIVE) dono se verify, 8 Nov 2026.
  • Footer social icons ka alignment Chrome screenshot se pixel-verified.
05

Phone pe — jahan zyada log aate hain

Zyada tar visitors mobile se aate hain. Purani site desktop layout ko mobile pe nichod rahi thi.

Kaise kiya

  • Breakpoints banaye (900/600/480px): nav → hamburger, grids → single column, gallery → 1-2 columns.
  • Overflow fixes: `overflow-x:clip` + har grid child pe `min-width:0` — lambi emails/handles bhi page nahi toda.
  • Ek-file architecture: WordPress/Elementor/plugin chain hata kar ek static page — isliye load time aur risk dono gayab.

Proof

  • Purani mobile pe element x=1052 pe (viewport 485px) — measure JSON mein record hai.
  • Purani load 3.27s + 27 files — live site pe 7 Nov 2026 measure.
  • Nayi site: 1440px aur 485px dono runs mein 0 overflow, 0 errors (Chrome headless, 8 Nov 2026).
  • Dono phone screenshots same size (500×900) — farak sirf design discipline ka hai.
06

Architecture — purana engine vs naya engine

Jo dikhta nahi wo sabse important hai: purani site ek heavy WordPress build thi, nayi ek halki, version-controlled, premium static build hai.

Kaise kiya

  • Poora brand hub ek file mein banaya (v1→v9, 7+ turnd ke upgrade) — design tokens (colors/type/spacing) CSS variables mein locked.
  • Har deploy pe: Chrome functional tests (tabs, links, errors, overflow) → phir GitHub push → Pages live (1-2 min).
  • Photos: company archive se li, resized/compressed — koi AI-generated image nahi, koi stock nahi.

Proof

  • Purani site ka stack: WordPress 7.1.4 + Elementor + The Plus Addons + Swiper — HTML source se verified.
  • 27 files / 3.27s — live measurement log (7 Nov 2026).
  • Nayi site: file byte-identical local vs LIVE (md5 match, har deploy ke baad verify hota hai).

Ye proof kaise pakda gaya (taaki koi shaq na rahe)

  2. Measured numbers: header ki height, logo rows ki positions, overflow elements, copyright lines — sab measure-*.json files mein saved hain (purani site ki DOM measurement).
  3. Link proof: nayi site ke saare external source links curl se check kiye (200 OK) — recognition strip wale bhi.
  4. Visual QA: Claude vision (Fable) ne screenshots dekhe aur page ka description diya — jo code kehta hai wahi screen pe hai.
  5. Deploy check: har update ke baad LIVE page ka md5 local file se match hota hai — jo tumhe dikh raha hai, wahi bheja gaya.
